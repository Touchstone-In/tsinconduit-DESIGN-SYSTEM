Collapsed rail — with categories

One icon per category, standing in for the whole group

What you're looking at

The rail reduces to --a-rail-collapsed (72px). Because this nav has categories, each labeled group collapses to a single icon representing the category — Applications, MMI, Screening & KYE — not one icon per destination. The category owning the active route keeps the active fill, so you can still see where you are.

Each group supplies its own icon; a group without one falls back to its first item's icon, so navs written before this existed still collapse to something meaningful. Every icon carries its label as a title and aria-label, so the name is available on hover and to screen readers.

Clicking a category icon restores the full rail with that group open, rather than navigating somewhere arbitrary — collapsed, the icon is the only handle onto the items underneath it.

The toggle under the brand mark always works. Unprompted reduction below a viewport width is opt-in: autoCollapseBelow defaults to 0, because the rail sizes its own host element and a host drawer with a hard-coded width would not follow it — leaving a 72px rail inside a 248px drawer. Give that drawer width: auto (or resize it from collapsedChange) and then set autoCollapseBelow to a breakpoint; 1280 is the Assay reference value. Crossing it clears a manual override, handing control back to the automatic behaviour.
